FreshStep: a map of the session-only release

Set a cigarette limit, log a count, and try a supportive activity. Completing an activity opens encouragement. Reloading returns to setup; progress is held only in page memory.

One action through the app

Click +→ app.js event handler→ domain.js adjustCount→ app.js render→ count, circle, support

Reference route

This is a take-home route, not a claim of an interactive code tour.

  1. docs/js/app.js: search for $('plus').addEventListener. The click updates the in-memory count and calls render().
  2. docs/js/domain.js: adjustCount prevents negative or unsafe counts; visualBand calculates green, yellow, or orange from the chosen limit.
  3. Back in app.js, render() updates the label, circle, buttons, and supportive text. HTML supplies the elements; CSS styles them.

To change this, start here

  • Page labels and session notice: docs/index.html.
  • Colors, spacing, narrow layout, reduced motion: docs/styles.css.
  • Activity steps and source links: docs/js/activities.js and docs/sources.md.
  • Threshold rules: domain.js and tests/domain.test.mjs. Change an observable requirement and its boundary checks together.

A practice to reuse

The agreed limit of 15 has precise boundaries: 9 is green, 10 and 15 yellow, and 16 orange. The test named “color boundaries are inclusive and graphical progress is capped” checks those examples. On another project, give an agent observable examples at the boundaries, run checks, and then try the visible result yourself. Automated logic checks do not establish that keyboard interaction or layout works.

Run and publish

From the repository root, run node scripts/serve.mjs and open localhost:4173. Run node --test for the existing checks.

Only docs/ is the website. Node serves it locally; GitHub Pages can serve the same static files from /docs. There is no hosted database or application API.
